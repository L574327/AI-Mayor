# AI Mayor：市长控制台 UI 与产品封装方案

状态：可交给车间评估和实现的设计方案，不是能力已经完成的声明。

配套文件：`ai-mayor-ui.html`，可离线打开。所有数值、状态及交互均为示例，不连接游戏、不实现真实编译器。顶部“查看状态”是设计演示工具，正式产品删除。

## 1. 产品形态

一个本地运行的市长产品，保留现有游戏 Bridge 和已有 TypeScript 运行时；在现有桌面应用中提供独立的“AI Mayor”工作区。复用现有宿主，不为了设计再造一套桌面壳或网页服务。

玩家体验：打开产品 → 连接当前游戏 → 一次确认接管目标和边界 → 市长持续照看城市 → 玩家需要时通过自然语言调整目标。

只有“自主经营”一个模式。发展、止损、服务维护、交通改善是当前工作重点，不是四个模式按钮。收支与服务恶化时先修复，有余力时发展。

窗口与运行时分离：界面关闭、表达器故障、云 AI 暂时不可用，都不能令本地已授权的自治任务停止。是否最小化到托盘，优先复用宿主已有能力；没有托盘能力不影响首版。首次关闭时应明确说明“市长是否仍在运行”，之后记住选择。停止市长与停止整个应用使用不同文案。

正式主界面不展示工具名、账本状态、开发树编号、命令 JSON、预检循环计数。诊断抽屉可以显示。

## 2. 视觉方向

安静、清晰、有证据的经营工具。默认深色，适合和游戏来回切换；同时支持浅色。少量蓝色表达交互与当前工作，绿色表达已确认，琥珀色表达等待或问题，红色只用于连接失败、持续恶化等需要关注的状态。

不用赛博霓虹、不使用仪表盘大圆环、不做头像养成、不把每个问题都做成一张色彩卡片。状态始终同时包含文字，不靠颜色传达。

字体使用 Windows 系统字体和 Microsoft YaHei；不加载在线字体或装饰图片。常规正文 14px，辅助说明 12px，主标题 24–26px；数值使用等宽数字。圆角 8–12px，基础间距 8px。按钮至少 36px 高；触屏布局目标 44px。

示例深色令牌：背景 #0E131B，内容面 #151D29，抬升面 #1B2533，分隔线 #293547，正文 #EEF3FA，次要文字 #A3B0C2，主交互 #8AB9FF。浅色令牌见原型。正式实现检查文字与实际背景的可读性。

不模拟完整操作系统窗口标题栏，避免与已有桌面宿主的窗口控件重复。

## 3. 信息架构与首页

四个主入口：城市、交办、记录、设置。所有页面保留右侧“市长汇报＋交办输入”。

桌面三列：左导航约 140–164px，中间经营内容自适应，右表达与输入约 280–306px。建议主窗口 1280×900 或更大，100%/125% 缩放均应可用；宽度不足时缩窄导航，再上下排列。窄布局把表达与输入接在经营内容后，不丢失暂停入口。

首页回答三个问题：城市怎样、现在做什么、我如何调整目标。

### 固定头部

- 当前城市与世界身份；最近真实读回时间。
- 游戏连接状态。诊断详情另列运行时连接，不把游戏与运行时混成一个健康灯。
- 接管边界入口。
- 主操作：开始接管／暂停市长／继续自治，随实际状态变化。

“暂停市长”停止发起新操作，不默认暂停游戏。正在提交或已提交的动作，需要等待确认或进入既有异常处理；按钮显示“正在暂停”，不能马上宣称已经停止。UI 禁用和防连点只是体验措施，真正的提交控制复用运行时能力。

### 四项城市读数

人口与游戏时间窗口内变化、可用资金、游戏提供的收支读数、交通读数。

数字来自游戏已有接口，不为填满界面构造健康评分。不存在的读口显示“未读取／当前版本不支持”；读取失败显示“读取失败”；过期读数保持数值但明确标“最后读回”。截断时显示读取范围和“部分数据”。

财务单位使用游戏币或当前游戏显示单位，不能把示例人民币符号理解成现实货币。时间窗口用“游戏日／游戏月”，刷新与异常时间用现实秒。

交通读口正式完成前，第四项显示缺口，不用拥堵图标数量伪装成流畅度。若新读口给的是另外一种指标，标签与单位必须匹配真实返回值。

### 当前工作

只展示一项正在推进的工作：标题、原因、当前阶段、资金与资产影响，以及“查看依据与步骤”。

四个阶段为“核实原因 → 游戏预检 → 执行读回 → 观察效果”。这只是结果的呈现方式，不要求新增运行时状态机。动作若不适用某阶段，按真实能力显示，而非硬套四步。

游戏确认修改成功与城市问题改善是两件事。未经过观察窗口，不显示“拥堵已解决”“服务已恢复”。阶段条表达事实，不显示猜测的百分比和倒计时。

下方最多三个“接下来值得处理”的问题组。按根因和影响聚合，无法确认共同根因时明确写“待诊断”。不要把一百个图标列成一百项任务。

### 市长汇报与交办

最新一轮简短汇报：正在做什么、依据是什么、为什么延后其他事情。每次最多两小段。不同页面保持同一份事实。

原型右栏的“已检查”卡提供证据摘要，不显示伪造成功率。朗读默认关闭；复用现有表达器，语音播放不阻塞施工。

输入固定在右栏下方。Ctrl+Enter 发送，Enter 换行。三个快捷文案只负责填入目标，不直接触发施工、不形成三个经营模式。

自然语言送入已有语义链。良性目标更新可直接显示已解析目标和取消／修正入口；只有范围不清、约束冲突、超出权限等情况才展示确认卡。原型统一使用确认卡，是为了让设计可检查，不要求正式产品每句话都确认。

接收目标不意味着施工完成。用户取消尚未确认的交办只取消该请求，不能撤销此前已经改变的世界。

## 4. 接管、交办、记录与设置

### 首次接管

一页对话框即可：经营目标、允许局部道路修改、允许经济调整、允许买地，以及保留对象／区域入口。默认保留已有建筑，不能把一个“允许改路”开关扩成自动拆房权限。

一次明确授权后，在约定范围内自治，不反复询问每次预检。保留对象和范围应由已有语义约束和目标选择能力承载；原型按钮不是已经具备游戏选择器的声明。

开始之前必须由已有存档原语创建独立原始备份并确认保存完成；复选框只代表用户同意，不是保存成功证据。保存失败时不进入接管。轮换检查点不覆盖这个备份。

检测到换图、读档或世界身份改变时，停止旧任务的新提交，并重新确认当前城市的授权适用性；同名城市不代表同一世界。不自动对新加载的城市沿用旧对象。

### 交办页

显示当前目标、工作范围、允许动作、保留约束；提供编辑。无须给玩家展开任务图或配置优先级权重。不能执行的意图保留原话，显示具体能力缺口，不擅自改成另一项任务。

### 记录页

按事件展示动作、游戏裁决、读回结果和效果。每项可展开依据。开发细节只在诊断导出或详情中。

本地经验仅显示：经验配方、适用条件、已确认的观察数，以及是否暂缓／过期。别把样本很少的成功率当成权威评分，也不显示“AI 智商成长”。没有效果证据的动作不能进入成功经验。

清除经验不能删除未决操作的重复提交保护。清除记录、清除经验、恢复游戏存档是三个不同操作。首版可以只提供清除本城经验与诊断导出。

导出默认不包含 API 密钥、账户凭据、玩家原始聊天；正式产品使用现有诊断导出流程与用户已授权范围。跨玩家上传学习不是首版必需功能。

### 设置页

只保留游戏连接、游戏模拟控制、备份状态、主题、界面语言、朗读，以及现有 AI 连接配置入口。API 高级设置折叠，沿用既有安全存储，不在 UI 代码里保存密钥。

外部 AI 不可用：说明“自然语言理解暂不可用，本地自治继续”；运行时不可用：说明“无法控制市长”；游戏不可用：说明“无法读取城市，停止新操作”。不能统称离线。

## 5. 异常状态的呈现

| 状态 | 主界面表达 | 行为 |
| --- | --- | --- |
| 暂无需要处理的问题 | 城市稳定，继续观察 | 正常待机，不判挂住 |
| 等待模拟效果 | 动作已确认，效果待观察 | 不重复干预同一对象，仍处理其他紧急问题 |
| 游戏暂停／里程碑弹窗 | 等待游戏继续／正在处理弹窗 | 不把游戏时间未前进当成施工失败 |
| 游戏暂忙 | 稍后继续，无有效裁决 | 不记经验失败 |
| 资金不足 | 此动作暂缓；显示所缺资金或条件 | 不撒点预检、不连续借贷 |
| 缺少能力 | 某项任务不能执行，其他维护继续 | 保留原意图，不假装完成 |
| 未决写操作 | 结果待确认 | 不能重复提交同一动作 |
| 部分读取 | 明确范围与截断 | 没读到不等于没有问题 |
| 连接中断／无有效进展 | 上方异常条，显示最后事实和恢复进度 | 复用监督者，目标 30 秒内发现并开始恢复 |
| 恢复成功 | 已恢复，说明确认了什么 | 先读世界再继续，不宣称已治好城市 |
| 恢复达到次数上限 | 已停止尝试，显示可理解的原因和下一步 | 保留记录，不无限循环 |
| 游戏退出 | 请启动游戏并加载城市 | 不擅自启动或加载玩家存档 |

异常提醒在状态变化时发送一次，恢复时一次；不要每轮朗读同一问题。UI 消失不应令监督者失效。窗口内提醒和宿主系统通知复用现有能力即可。

## 6. 最小英文支持方案

结论：保持一份意图模型、一套本地编译器和同一套 UI 布局。不要为了英文重新建游戏规则、经营 Profile 或 Planner。

### 优先路径：同一语义前端直接接受英文

先用真实语义前端测试英文能否输出当前既有 MayorIntent。如果能，改系统说明与语言输入设置即可；枚举值、类型、单位规则和编译器完全保持原样。

英文原话 → 现有外部 AI 语义前端 → 同一 MayorIntent → 原有本地 Compiler → 原有执行链。

现有系统若依赖中文关键词或中文枚举，先定位依赖发生在哪层。不能仅凭大模型会英文便宣布整条链支持英文。

### 备选路径：中文标准化适配器

若前端确实必须收中文，可以只在它前面添加输入适配：英文原话 → 中文标准化文本 → 现有前端。优先与原有 AI 调用合并完成，避免每次交办固定增加一轮远程请求。

原话、源语言、标准化文本放在请求封装里，尽量不扩张冻结的 MayorIntent。保留字面实体名、对象 ID、坐标、数字与单位；明确处理范围、例外、否定、数量限制和授权，不得“润色”掉约束。

例如 `Improve traffic in "East Bank", but don't demolish homes or buy land.`：区域字面名 `East Bank` 原样保留，不自动改成“东岸”；保留“不拆住宅、不买地”。如果当前世界不存在这个字面对象，走原有 UNKNOWN／歧义处理，而不是猜一个附近区域。

如果用户说的是通用类型 small road，则映射到已有规范类型；游戏对象实际名称和 prefab 标识仍由本地解析。显示语言不能充当对象身份。单位转换只使用既有编译规则，不由翻译模型随意换算。

中文中间文本不自动代表语义完全忠实。适配器无法判定的指代、冲突或条件使用既有不确定性机制，并把必要确认显示成玩家原语言。

### 表达器输出英文

同一份已确认事实 → 原有表达器的英文输出设置，或者表达器最后增加英文格式化适配。不能让英文表达器重新推理城市、决定动作、补造结果。常见状态先使用中英模板；复杂说明复用已有模型调用，不必增加每轮翻译服务。

数字、对象身份、执行阶段与确认状态不可随表达改变；尤其区别 `submitted`、`confirmed by game`、`effect not yet confirmed`。英文叙述不重新送入执行链。

### UI 的最小本地化

静态按钮、状态、设置项使用集中字典 `zh-CN`／`en`；沿用现有 i18n 设施。如果没有，简单键值查找和模板插值已够，不必新引入整套多语言框架。

示例键：`nav.city`（城市／City）、`nav.mission`（交办／Instructions）、`nav.records`（记录／Activity）、`nav.settings`（设置／Settings）、`mayor.pause`（暂停市长／Pause mayor）、`game.pause`（暂停游戏／Pause simulation）、`status.effect_pending`（效果待确认／Effect not yet confirmed）、`metric.unavailable`（未读取／Unavailable）。

界面语言、玩家输入语言、游戏显示语言是三个独立来源。用户可覆盖系统默认语言。原始建筑名默认照游戏显示，不自动翻译。布局给英文文案留空间；不要固定按钮宽度或把文本烘焙成图片。

当前可交互原型展示中文设计，不宣称已经完成产品英文支持。车间按同一布局替换文案即可。

最小验收语料：至少 12 对中英等价交办，覆盖目标、区域、保留、否定、例外、数字单位、顺序、条件、取消、修改、歧义和超出能力。两种语言应产生等价的规范语义或相同的不确定性结果。比较规范结果，不能要求随机表达逐字一致。英文若未通过这一步，不标“完整英文支持”。

## 7. 前端实现边界

复用现有组件、状态通信、日志和 AI 配置。UI 是已有系统的呈现层，不新增世界对账层、调度平台或持久工作流。

最小页面组件：AppShell、CityOverview、CurrentWork、NextIssues、MayorNarration、IntentComposer、TakeoverDialog、MissionView、ActivityView、SettingsView。四页可用现有路由或普通视图切换；没有必要建立复杂导航。

适配现有数据形成只读视图，不要求建立第二套权威状态。所需字段的职责：

- 世界身份、运行状态、最近读回时刻及数据完整性。
- 游戏已有的城市指标与对应窗口／单位。
- 当前任务描述、阶段、成本、权限范围、确认结果。
- 下一批问题组、证据及原因是否已确认。
- 表达器最新事实汇报、当前交办与接管约束。
- 历史事件和经验摘要。

更新频率沿用现有世界读取节奏；UI 不另起全城扫描、不为动画触发 Bridge 请求。可以由推送或既有轮询刷新视图，隐藏页面不请求细节；展开时再读所需对象。异常监督独立于 UI 刷新。

后端拒绝或缺少权限时，界面反映拒绝；不能仅凭 UI 开关开放本地施工权限。切换目标／城市／语言都不能重复提交已开始的动作。

局部道路图不是首版必要。原型中的 SVG 是示意图，实际优先使用“在游戏中定位”以及现有截图／摄像机能力，避免重建一套 GIS 和实时 3D 城市渲染器。目标选择能力没完成时显示缺口，不以装饰地图掩盖。

## 8. 本轮实现范围与验收

授权车间先对照现有能力校准字段和可用入口，必要时调整实现方式，但保留本方案的用户体验。然后连续完成界面接线、已有回归、真实游戏验证。不要每做完一页就请求继续。

首版需要：四个页面；一次接管与原始备份确认；当前工作、真实读数和异常状态；自然语言交办接现有编译链；现有表达器接右栏；经验和诊断记录的最小呈现；中英静态字典与语义前端英文验收。

首版不需要：自研地图引擎、三维城市场景、自动回档、一键宣称治好城市、成长等级、跨玩家经验市场、用云 AI 指挥每次施工。

验收重点：

1. 所有数字和“已完成”状态能对应真实游戏读回；截断、缺口、过期均可辨认。
2. 暂停市长不暂停游戏；有未决动作时不假装已经停止；恢复不重复施工。
3. 首次接管先确认实际备份和权限；换城市不沿用旧对象。
4. 修改交办能到达已有 Compiler；不支持或有歧义时明确返回，保护约束保持有效。
5. 表达与施工使用同一事实结果，叙述输出无权限触发施工。
6. 1280×900、1024×768、Windows 125% 缩放可用；键盘、焦点、对话框关闭正常。
7. 连接断开、效果等待、能力缺口和资金不足各实测一次；监督者不用 UI 才能工作。
8. 英文语料对照中文产生等价规范结果；未通过的能力明确标示，而非翻译后默认成功。

UI 接线遇到缺口，只补这一条体验确实需要的适配。涉及道路治理或语义核心更改，应由车间依据本地实现判定，不能把设计原型当成已有游戏能力。
