# FAST\_EXPANSION\_V2 Gameplay Policy Candidate

Oct 4, 2026 · @li

## 范围与状态

本文是 FAST\_EXPANSION 的 V2 玩法策略候选，目标是在不发生不可恢复财政崩溃的前提下，最小化真实 time-to-100k。裁决结论为 MAJOR\_REVISION：保留现有 world readback、policy、planner 骨架，重写阶段切换、批量大小、密度选择、买地四处策略。

- **适用版本**：Cities: Skylines II 1.6.2f1（2026-09-15）。版本升级后，所有带版本标注的规则进入待复核状态。
- **⟨待标定⟩ 占位值**：所有尖括号阈值先用保守占位值上线，由第 9 节的实验标定，不得当作已验证数值。
- **证据来源**：视频研究（Gemini）只采信行为模式，不采信具体数字；机制研究（DeepSeek）中的 Wiki 数值多停留在 1.0 版本，同样降级处理。
- **不在本文范围**：代码实现、新 AI 架构、Semantic Compiler 扩展。

## P1 · 阶段机：以里程碑切换，不以人口切换

阶段由里程碑等级驱动，因为 XP、里程碑、解锁、人口是同一个正反馈环（机制证据 A1、A2）。

| 阶段 | 进入条件 | 主目标 | 主建造类型 |
| --- | --- | --- | --- |
| S0 启动 | M0–M1 | 现金流不崩，拿到 M2 | 小片低密、M0 特化工业、最小公用事业 |
| S1 中密 | 达到 M2 | 冲 M4 / M5 | Row / Medium 为主，低密只填零碎地块 |
| S2 资本与通道 | 达到 M4 | 现金流转正，建第二条外部通道，冲 M8 | Medium、低密办公、交通枢纽（解锁后） |
| S3 高密 | 达到 M8 | 高密主力扩张 | HD 住宅 + HD 商业（M9）+ HD 办公（M10） |
| S4 尾段 | 人口 ≥ ⟨\~50k⟩ 或观测迁入速率开始衰减 | 解除当时绑定的那一个约束 | 由 P6 瓶颈诊断决定 |

**主动 XP 动作规则：** 距下一里程碑的 XP 差距小于 ⟨待标定⟩，且满足 P8 财务条件时，允许放置服务建筑或升级、放置 Signature（需满足 P3 的同类空置条件）、铺设计划内的道路和管线。不允许为了 XP 建造计划外的设施。

**证据状态：** 主动 XP 的方向有机制支持，但单个动作相对人口 XP 的比值未知，XP 更新频率（16 次/天还是 32 次/天）也有冲突，见实验 E3。

## P2 · 批量大小 = min(资本上限, 吸收上限)

固定 batch 被废弃，因为迁入速率随人口对数衰减，且同密度空置会反噬 demand；批量必须同时受资本和吸收能力约束。

- **吸收上限**（按密度分别计算）：观测净迁入速率 × 前瞻窗口 − 该密度当前空置单元数。结果 ≤ 0 时，该密度本轮不新建。
- **资本上限**：可支配现金 × ⟨比例⟩ + 月盈余 × ⟨月数⟩，且必须留足储备金 ≥ ⟨N 个月总维护费⟩。
- **实际批量**取两者较小值。
- **资本强、吸收弱时**，余钱用于公用事业 headroom、外部通道和 XP 动作，不继续铺住宅。
- **执行方式**：大批次一次性下发。是否暂停游戏由 planner 的执行耗时决定，不属于策略规则。

每次决策都要记录是资本上限还是吸收上限在约束，供基准对比使用。

## P3 · 密度选择：默认最高已解锁密度，低密设配额

密度由解锁状态和空置率决定，不由 demand bar 的高低决定；"M8 后彻底禁止低密"被否决，改为降权加配额。

- **默认**选择当前已解锁的最高住宅密度。
- **低密只在三种情况下使用：** S0 阶段；地块形状不适合更高密度；LD 空置率 < ⟨阈值⟩ 且 LD demand 高（服务富裕家庭）。M8 之后低密新建量受配额上限约束。
- **demand bar 只用于排除**某个密度（空置高或 demand 为 0 时不建），不用于选择低密。
- **只对未开发的已划区地块** rezoning 升密。已开发的低密不拆，除非建筑已废弃或濒危。
- 划区后超过 ⟨N 天⟩ 仍未开发的地块，撤回 zoning（EmptyZones 是独立的 demand 抑制因子）。

**待验证：** household 是否会拒绝非偏好密度尚无定论（实验 E4），它决定低密配额的大小。

## P4 · 就业与住房：保证存在可用岗位，不追求零失业

住宅 demand 与可用岗位正相关，Economy 2.0 本身就预期失业率上升，所以目标是"岗位略多于求职者"。

- **目标状态**：岗位空缺率 ≥ ⟨阈值⟩，不以 0% 失业为目标。
- **住宅 demand ≤ 0 且失业率偏高时**优先补岗位：S2 阶段补工业或低密办公，S3 阶段补 HD 办公或 Signature 办公。
- **Office demand bar 不作为信号。** 是否需要办公岗位，由失业率和受教育待业人口判断，效果由读回的岗位填充率验证。
- **商业扩张**以店铺平均库存正常为前提。出现 "Not enough customers" 时先查供应链，不加住宅也不拆商业。
- **税率**只作为岗位侧杠杆（降办公或工业税），不作为住宅侧杠杆。视频作者本人承认住宅减税无效。

## P5 · 买地：按交付提前量购买，不拖到最后一秒

买地成本递增且追溯：多买一块会推高全部已购地块的 upkeep（比例约 5% 升至 25%），所以买地必须是有理由的动作。

- **只在三种情况下买地：** ① 外部连接或战略通道需要（优先水地块）；② 已拥有地块内可开发面积 < 下一批次需求 × ⟨1.x⟩；③ 必需的资源地块。
- **每次买地**都要计算全图 tile upkeep 的追溯增量，并计入 P8 的现金流检查。
- **S3 阶段**的 HD 扩张优先使用飞地新地块，而不是推平已开发区域，同时计入远距离输电和供水成本。
- **不采用**"动工前一秒才买"的绝对说法：买得太晚，公用事业铺设和建筑生长的时间会让 spawn 窗口空转。

**待验证：** upkeep 曲线的精确函数（实验 E9）。

## P6 · 外部连接与瓶颈诊断（S4 的核心）

外部连接是增长前置条件，但不是唯一瓶颈：先判断是需求、通道还是供给问题，再决定动作。铁路是否比道路连接迁入更快尚无证据，需用实验 E1 验证。

## P7 · 公用事业与服务：保留余量，分三档处理问题

短缺是 Major problem 且会连锁打击企业效率和人口留存，而过剩可以用服务预算（50–150%）便宜地吸收，所以策略是保留余量。

- **容量余量**：电、水、污水容量 ≥ 峰值负荷 × ⟨1.2–1.3⟩。过剩用服务预算（≤100%）吸收。
- **电源选择**枚举所有已解锁类型，按"每 MW 月成本，含出口收益"排序，删除 WindTurbine-only 限制。出口只是 headroom 的副产品，实验 E6 通过之前不作为主动收入策略。
- **远距离扩张**检查输电和输水路径容量，不能只依赖道路自带的 40 MW。
- **拥堵**用 Traffic infoview 的梯度读回判断，不看图标（图标需 ≥10 辆车互相阻塞，且每 64 tick 才检测一次）。修拥堵优先改路口形态（T 字口、立体过街），不全线拓宽，因为大路会增加噪音并压低地价。

| 档位 | 通知 | 处理方式 |
| --- | --- | --- |
| 立即修复 | 缺电或电力瓶颈、缺水或污水倒灌、无道路连通、垃圾堆积、等待救护车或灵车、取水污染、火灾、倒塌、废弃 | 当轮优先处理。垃圾自 1.6.2 起对 happiness 影响放大，需先检查垃圾车是否出得去 |
| 暂缓 | 缺高技能劳动力、租金过高、设施满载、各类污染 | 按周期批量处理，不逐个反应 |
| 不机械响应 | Not enough customers、High resource costs、Leveled up、个别寻路失败 | 先查根因（供应链、采购、单条线路），不见图标就施工 |

不追求全绿：服务建筑本身有维护费，并会制造噪音和污染。

## P8 · 财政与贷款，P9 · 版本绑定

贷款利率随"借入额 / 信用度"比值上升，所以贷款决策看借用比例，不看有无债务。

**P8 硬约束：** 现金储备 ≥ ⟨N 个月维护费⟩，且滚动月盈余不能连续 ⟨K 个月⟩ 为负，否则冻结扩张，只保留修复动作。

| 借入额 / 贷款上限 | 允许用途 | 含义 |
| --- | --- | --- |
| 低于 ⟨\~30%⟩ | 有明确回报的项目：临近里程碑的 XP 动作、外部通道、公用事业 | 真杠杆 |
| ⟨30–70%⟩ | 只用于修复 | 边际成本上升 |
| 高于 ⟨70%⟩ | 触发削减支出（降服务预算、暂停买地） | 结构性亏损信号 |

水电收费滑块作为 WORLD\_DEPENDENT 旋钮：财政紧张时上调，宽松时下调以换取效率和 happiness。Wiki 中的百分比系数停留在 1.0 版本，需读回确认。

**P9 版本绑定：** 所有阈值和 bug 绕行逻辑（office demand、mixed housing 等）标注适用版本（当前 1.6.2f1）。版本升级后，相关规则自动进入待复核状态。

## 实时验证队列：按对 time-to-100k 的预期收益排序

E1 到 E3 最可能显著改变 time-to-100k，应先做；E1 决定铁路是否应成为 S2 的强制动作。

| # | 实验 | 设计要点 | 会改变什么 |
| --- | --- | --- | --- |
| E1 | 外部通道是否是 30k–100k 的绑定约束；铁路与道路连接的差异 | 同一约 30k 存档点（有空置、demand > 0）分三组：对照、新增道路外部连接、新增铁路外部连接，测后续 N 个游戏日净迁入速率 | P6 分支 2 是否成立；铁路是否强制 |
| E2 | Spawn 上限标定 | 在 5k / 20k / 50k / 80k 人口点，住房和通道都充足时测每游戏日最大净迁入量，反推 spawnSpeedFactor | P2 吸收上限；time-to-100k 的理论下限 |
| E3 | Signature 与服务建筑的 XP 价值 | 从 M2 存档点比较有无 XP rush 到达 M8 的时间；读回单个动作 XP；核对 16 或 32 次/天 | P1 主动 XP 动作的权重 |
| E4 | 密度偏好是否导致拒住 | LD demand 高时只提供 HD 住房，测入住率 | P3 低密配额大小 |
| E5 | 尾段岗位杠杆 | 约 80k 时对比降办公税、新增 HD 办公区、对照组的净迁入速率 | S4 阶段 P4 的主动作 |
| E6 | 电源经济性（1.6.2） | 读回各电源每 MW 月维护费和出口单价 | P7 出口能否作为主动收入 |
| E7 | 交通负载对模拟速度的影响 | 同一人口下，比较高、低车流布局每真实分钟的游戏 tick 数 | 交通设计是否计入 real-time 目标 |
| E8 | 飞地扩张与原地升密 | 同等预算下，新地块建 HD 对比拆旧低密改 HD，30 游戏日后比人口增量 | 校准 P3 和 P5 |
| E9 | Tile upkeep 曲线 | 读回 9 / 15 / 20 / 25 块地块数下的 upkeep | P5 追溯成本由估算变实值 |
| E10 | EmptyZones 抑制强度 | 划 100 格空区，观察 demand 曲线 | P3 撤回 zoning 的阈值 |

## 当前 Mayor 应删除的旧策略

以下十项直接删除或废弃，而不是在旧逻辑上叠加新规则。

1. 固定 batch size，由 P2 取代。
2. 按各密度 demand bar 高低选择 zoning 类型，这是 10k 人仍大量铺低密的直接原因。
3. 按人口或建设进度自动买地的线性扩张触发，由 P5 取代。
4. WindTurbine-only 的电源枚举，以及所有写死的单一电源类型，由 P7 全枚举排序取代。
5. 见通知就施工的逐条反应式修复，由 P7 三档分类取代。
6. 以 Traffic jam 图标判断拥堵的逻辑，以及"拥堵就拓宽道路"的默认动作。
7. 以 0% 失业为目标的逻辑。
8. 以 office demand bar 为正作为建办公前提的逻辑。
9. 1.5.7 之前的 bug 绕行逻辑（规避 Mixed Housing，或把 Not enough customers 当 bug 忽略），如果存在。
10. 不检查空置率的住宅新建逻辑，以及划区后不回收的行为。

## 基准协议：干净 checkpoint 的 100k 对比

主指标是真实 time-to-100k；V1（当前策略）与 V2 各至少跑 2 次，因为迁入和建筑生长有随机性。

**固定条件**

- 游戏版本 1.6.2f1，除 Mayor 外不加载其他 mod，同一张地图，同一个 0 人口初始存档；另备一个约 30k 的中期 checkpoint，单独比较尾段。
- 同一台硬件，固定模拟速度设置，并记录实际倍速档位（3x 与 8x 的差异必须写明）。
- 终止条件：达到 100k；或出现不可恢复的财政崩溃（P8 冻结后 ⟨K 个月⟩ 仍为负）；或真实时间超过 ⟨上限⟩。

**采样：** 每个游戏日一次，同时记录真实时间戳。

| 类别 | 字段 |
| --- | --- |
| 时间 | 真实时间；游戏模拟时间；每真实分钟 tick 数 |
| 人口 | 总人口；净迁入 / 迁出；到达 1k / 5k / 10k / 20k / 50k / 80k / 100k 的时刻 |
| 里程碑 | 当前等级；XP；各里程碑达成时刻；主动 XP 动作次数与对应 XP |
| 财政 | 现金；月收支；贷款余额与借用比例；tile upkeep；服务维护费 |
| 密度 | 各密度单元数与住户数；各密度新建量 |
| 空置 | 各密度空置单元数与空置率；已划区未开发格数 |
| 就业 | 岗位总数；空缺数；失业率；按教育水平的错配 |
| 土地 | 拥有地块数；可开发剩余面积 |
| 公用事业 | 电、水、污水容量 / 峰值负荷比；进出口量；服务预算设定 |
| 外部连接 | 每条连接利用率；按连接类型统计的迁入人数 |
| 通知 | Major / Problem 级通知数量与持续时长，按类型分别统计 |
| 施工吞吐 | 每游戏日新建单元数；建造支出；P2 中资本上限与吸收上限哪个在约束 |
| 诊断 | 每次 P6 命中的分支，以及当时被绑定的约束 |

**核心对比指标**

- 主指标：真实 time-to-100k。副指标：模拟 time-to-100k、time-to-M8。
- 效率指标：每百万 ₡ 换来的人口增量；空置单元 × 天的积分；Major 通知 × 天的积分。
- 安全指标：最低现金点；峰值借用比例。
