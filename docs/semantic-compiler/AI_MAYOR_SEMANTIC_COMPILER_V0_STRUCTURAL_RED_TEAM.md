# AI Mayor Semantic Compiler V0 — Structural Falsification Red Team

输入：`AI_MAYOR_SEMANTIC_COMPILER_UNIFIED_V0(1).md`，全文 763 行。审计日期：2026-10-04 UTC。

本轮仅审计这份研究基线。不读取仓库、不核验当前游戏能力、不调用实际 Compiler、不追加外部研究。下面的“失败”是规范反例与欠定义证明，不是已运行程序的实测错误。

语料限制：统一稿保留 T001–T370 的分类账和部分摘要，没有收录 370 条完整原句。本报告复用其中可核对的 case 摘要；注明“变体”的文字是本轮构造，不冒充 Grok 原文。不根据编号账推算准确率。

## 1. RED_TEAM_VERDICT

**SURVIVES_WITH_REQUIRED_REVISIONS**

**冻结架构尚未被推翻；V0 的权限、更新与验收契约未闭合，不能直接作为实现规范。**

没有证明“有限类型语义 → 确定性本地编译”在原则上不成立。发现的是：V0 对同一组合法声明，仍允许实现者作出互不等价的选择。部分选择会拆错区域、复活已取消目标、绕过等待条件，或把玩家没实现的目标报告为成功。

不能把 `scope/aspects/revision` 字段齐全视为解决：承重问题是这些字段如何共同求值、如何跨修订保持含义，以及未知事实如何限制执行与完成。

文档已明确防住、不能冒充新发现的问题：

- 小范围优化不自动覆盖全城 hard；Profile 不授予拆迁或贷款权。
- CANCEL 不物理回滚；已提交 zoning 是世界事实。
- STYLE、FORM、密度、高度相互独立；缓冲距离不证明零污染。
- OPAQUE/residue 不等于可执行；能力增加不自动扩权。

这些规范方向正确。本轮攻击它们尚未给出唯一结果的交界处。

## 2. STRUCTURAL_FAILURES

严重度：**CRITICAL**＝可越权改变世界或抹除重要保护；**HIGH**＝可持续违背 Mission、丢义或虚报完成。以下“likely interpretation”指合理实现分叉，不声称 V0 已要求错误实现。

### SF01 — 合法 IR 不能证明玩家原意被保真翻译

- **Failing input：**“不要不建商业”；“巴黎感，但不要巴黎式道路”；“宁可慢一点也不能拆老城”。前端分别交来“禁止商业”“欧式外观＋放射路网”“保护老城：PREFERRED”的合法声明。
- **Expected semantic meaning：**第一句不允许完全不建商业，不等于禁止商业；第二句排除道路方面的巴黎式模仿；第三句拆迁禁令是 hard，速度可让步。
- **Current V0 likely interpretation：**§3.1/§4.1 的类型、来源、极性校验可通过这些形式合法但含义错误的 IR。原文存入 source 后，本地禁止自由语言推理，不能靠保存原文自动发现所有删义、增义或强度变化。
- **Failure class：**Semantic fidelity / 信任边界。可确定性校验的是类型化声明，不是任意原话与声明的等价性。
- **Severity：HIGH；可能破坏游戏：是。**硬保护被降软后可能拆城。
- **Minimal repair exists：部分存在。**必须明确端到端保真仍是独立待证假设；不能声称 Compiler 合法性校验已覆盖它。类型化否定、例外、优先关系必须有固定解释，手写 IR 实验必须另有原意 oracle。该实验即使全过，也不证明任意自然语言翻译正确。

这是承诺边界问题，不是要求往本地再塞一个 AI。若产品要求“任何前端误译都由无语言推理的 Compiler 自动修正”，这项要求在当前架构下不成立。

### SF02 — 显式例外仍未定义它究竟修改哪个禁令

- **Failing input：**A：“全城禁拆，地铁永久保留。”B：“允许东区重建，但地铁仍不能动。”
- **Expected semantic meaning：**B 对全城拆迁禁令建立东区例外；西区禁拆继续有效；地铁保护继续有效。获得许可不等于必须拆。
- **Current V0 likely interpretation：**§4.2 的 hard 取交与 S04 的 ALLOW 不能绕 preserve，可能令东区仍完全不可拆；另一实现可能因“明确例外”删除全城禁拆甚至全部保护。文档允许 exception/revision，却没有绑定被修改规则及残余范围的共同契约。
- **Failure class：**Scope / permission / constraint merge 欠定义；禁止、保护、许可的作用对象混淆。
- **Severity：CRITICAL；可能破坏游戏：是。**例外可能泄漏到西区或地铁。
- **Minimal repair exists：是。**明确例外所修改的规则、范围和方面；仅裁剪相应旧限制，其他保护仍求交。不能以“最新”或“更局部”代替显式修改关系。

注意：旧禁令没有被明确修改时，新增窄 ALLOW 应保持禁令有效；明确修改了旧禁令时，又不能机械求交导致合法例外永远无效。

### SF03 — CANCEL 的“停止”与“恢复上一个声明”没有分开

- **Failing sequence：**A：“建欧洲紧凑城市。”B：“东边以后改美式郊区，其他不动。”B 已建出一片美式区。C：“刚才东边那个改动取消。”
- **Expected semantic meaning：**已建美式区不回滚。C 至少取消 B 的未兑现追求；是否恢复 A 的未来欧式规则，仅凭这句话未必唯一。不能把“取消目标”“撤销补丁”“恢复旧规则”默认为同一个操作。
- **Current V0 likely interpretation：**§5.1 的 CANCEL 可删除 B，再让仍保留的 A 自动覆盖东边；也可停止东边一切建设；也可停美式追求但继续 A 的人口增长。三者都不物理回滚，却有不同未来行为。
- **Failure class：**Revision / 声明继承与取消语义欠定义。
- **Severity：HIGH；可能破坏游戏：是。**未来建设方向被改，若旧纠偏授权复活，还可能拆已建美式资产。
- **Minimal repair exists：是。**取消对象与取消效果必须唯一；旧声明是否重新生效必须有明确契约。句子不能唯一绑定时，相关新写入阻塞，不猜“恢复”。显式恢复旧规则只能改变未来声明，仍不恢复世界。

### SF04 — 条件、许可与目标的存续关系缺失

- **Failing sequences：**①“等我回来再扩张”→“屋顶偏蓝”；②“到两万人才建地铁，允许为此拆东区这排房”→“地铁取消，其他继续”。
- **Expected semantic meaning：**①无关 style PATCH 不构成回来/放行事件。②取消地铁不留下可被其他目标使用的专项拆迁权；独立存在的老城保护仍存续。
- **Current V0 likely interpretation：**§4.1 把目标、时间门和 permission 分成不同产物，§5.1 又规定取消不影响其他保护。缺少明确关联时，重建 GoalSet 可能丢门；permission envelope 可能残留已失去用途的 grant。反过来，一刀取消关联子句又可能删除独立保护。
- **Failure class：**Revision locality / permission lifetime / temporal ownership。
- **Severity：CRITICAL；可能破坏游戏：是。**等待中开工或把地铁拆迁许可用于商业项目。
- **Minimal repair exists：是。**确定哪些条件和授权属于哪个目标，哪些是独立长期规则；取消、替换、完成分别如何影响这些规则。没有作用关系的许可不能凭同区域自动复用。

§5.4 已要求等待持续有效，但单条示例未定义一般关联机制；本项攻击的是如何让该要求在所有 PATCH/CANCEL 中成立。

### SF05 — SNAPSHOT 保护可在“重新解析”时被悄悄换基线

- **Failing sequence：**A：“西区保持刚才状态。”接受时有建筑集合 W₀；随后玩家或模拟改变了其中一栋。B：“东区以后用红屋顶。”
- **Expected semantic meaning：**无关 B 不重定义 A 的时间参照。A 原先承诺保护哪些对象/方面仍须可追溯；自然变化可影响当前可兑现性，但不能自动变成 A 的新 baseline。也不能因此偷偷恢复建筑。
- **Current V0 likely interpretation：**§4.1 从 Latest World 解析 scope、S03 在本地建立 baseline、PRESERVE 捕获当前世界。若每次编译都重捕获，旧保护失去历史对象或把变化悄悄合法化。若按新市中心重算“西”，保护还会空间漂移。
- **Failure class：**Scope / baseline identity / revision locality。
- **Severity：CRITICAL；可能破坏游戏：是。**原本受保护对象可能退出集合，被后续拆改。
- **Minimal repair exists：是。**SNAPSHOT 在原声明接受时绑定；无关修订只重验有效性，不重新取样。DYNAMIC 可重求集合，但选择基准、失效与新增成员规则要固定。不存在对象不能静默替换成同名对象。

“世界是事实来源”回答现在有什么；不能替代“用户当时保护的是什么”。这不要求城市物理回滚。

### SF06 — 范围内合法操作，不等于范围外没有受保护影响

- **Failing input：**“东区道路可重建，西区建筑和用途不动”；候选东区道路改动删除跨区连接，西区受保护住宅失去唯一接入。
- **Expected semantic meaning：**道路修改许可不能自动覆盖西区被保护方面；如果请求只是“不直接拆房”，又不能擅自把它扩成“保证所有住宅永不受经济影响”。承诺的方面必须明确。
- **Current V0 likely interpretation：**S01 scope filter＋D02 直接/间接影响预检方向正确，但未规定影响不完整/不可知时是否能执行。只查几何重叠会放行；试图预测无限未来模拟影响则没有可判定边界。
- **Failure class：**Permission / preservation effect boundary / unknown effects。
- **Severity：CRITICAL；可能破坏游戏：是。**接入、管线、用途或建筑可在区外遭破坏。
- **Minimal repair exists：是，但相关操作可能必须拒绝。**声明有限可检查的影响方面与覆盖边界；未知的相关副作用不能作“无影响”。若保证的是接入/服务，必须有相应观测；若只保证无 AI 直接拆改，不能报告完整世界不变。

同样，“只保护外观，不保护用途”不是任意改用途权：用途改变若连带换模型，仍须检查外观保护。

### SF07 — “可独立推进”依赖一个尚不存在的判断

- **Failing input：**“在这个选区建港口工业城，必须不让工业污染住宅”；本地只会距离隔离，没有污染观测。系统先建设“独立的”工业与住宅；候选布局用尽选区，之后无法增加隔离或调整而不拆迁。
- **Expected semantic meaning：**不能以部分施工推进不可分割的 hard 承诺，不能在尚无兑现依据时把该承诺当作稍后补上。
- **Current V0 likely interpretation：**§4.2.7 与 M11 允许独立且不破坏未来可行性的部分继续；但没有定义怎样证明“独立”和“未来可行”。不同 Concept 名称、不同施工种类都不能提供证明。
- **Failure class：**Unsupported hard / partial execution / future feasibility。
- **Severity：CRITICAL；可能破坏游戏：是。**不可逆占地、支出或污染源让目标更难甚至无法完成。
- **Minimal repair exists：是。**只允许由有限映射契约证明影响不相交、或具明确资源/空间预留证据的部分；没有证据则阻塞相关部分。无需证明任意城市计划的未来可行性；但不能凭常识猜独立。

这比“最后别说 COMPLETE”更严格：诚实说 PARTIAL 不能为已违反 hard 的施工补授权。

### SF08 — 单概念映射成立，组合的效果却可能互相改写

- **Failing inputs：**LOW_RISE＋HIGH_DENSITY；COMPACT＋LOW_DENSITY；GRID＋ORGANIC；EUROPEAN appearance＋Tokyo-like mobility；INDUSTRIAL_LOGISTICS＋LOW_POLLUTION。
- **Expected semantic meaning：**独立方面保留；同方面冲突检查到 scope/time/强度；物理容量未知不能当逻辑矛盾；两个 soft 允许取舍但须报告。仅当同一网络、同一尺度、同一时间要求“纯网格”与“无网格”时才有确定矛盾。
- **Current V0 likely interpretation：**O01–O16 已分轴，但 C02/M12 未给映射共用参数的合并规则。COMPACT 模板写密度下限、Tokyo 模板写高密、GRID/ORGANIC 写同一个 generator selector，最后应用的模板会改掉先前约束。
- **Failure class：**Concept composition / lowering / local determinism。
- **Severity：HIGH；可能破坏游戏：是。**高楼、扩张、路网重构或污染布局可能违背 hard。
- **Minimal repair exists：是。**每个有限映射声明所写效果、附带假设和约束；组合先验证全部 hard，再按固定规则处理 soft。不能拿模板隐含参数补充玩家语义；未定义组合应诊断或拒绝，不能交 AI 临场理解。

本项不证明要增加 Ontology，也不要求任意组合都能建成；要求不能用“Concept 可组合”替代 backend 效果组合证明。

### SF09 — Profile 可以通过“永久不推进”覆盖 Mission

- **Failing input：**“钱可以亏，禁止贷款；必须现在开始建设。”世界有足够现金，存在不需贷款且满足保护的合法建设候选；FINANCIAL_RECOVERY 仍持续等待其自设盈利阈值。
- **Expected semantic meaning：**允许亏损不创造现金，也不取消玩家已有硬现金底线；在本例已存在合法可执行候选时，经营偏好不能无限期否决“现在开始”。
- **Current V0 likely interpretation：**§4.1 的 profile compatibility 检查合法范围，M06 的财政底线来源未定。实现可能把 Profile 盈利门槛包装成硬准入，所有权限均未越界，却永远不履行 Mission。
- **Failure class：**Mission vs Profile / liveness / hidden constraint。
- **Severity：HIGH；可能破坏游戏：通常否，但可让产品永久空转。**
- **Minimal repair exists：是。**区分玩家 hard、实际资源/引擎限制与 Profile 可让步偏好；存在合法候选却仅因 Profile 偏好停滞时必须暴露原因并服从 Mission。不存在合法候选则明确 BLOCKED，不能伪报推进。

不要求建造不可支付的资产，不增加凭空财政安全线，也不要求所有 Mission 必有解。

### SF10 — 验收可通过移动分母、清空受体或丢弃未支持子句作弊

- **Failing inputs：**“工业不要影响住宅”；“这里以后保持安静”；“建高密但低层城区”；“巴黎感市中心，不能拆老城”。
- **Expected semantic meaning：**玩家要求的对象、分母、时间与目标组合保持原义。住宅全部消失、把道路面积排除分母、只验建成的两栋、忽略巴黎感，不能默认是原目标达成。
- **Current V0 likely interpretation：**§4.3 已分完成证据，但未规定空集合、缺测、统计集合变化和 Mission 总体聚合。污染 evaluator 对零住宅返回 true；楼高 evaluator 只检查当前存在建筑；所有“支持目标”完成后把 OPAQUE 从总完成条件中排除。REACH 一次阈值被用于“以后保持”的 MAINTAIN。
- **Failure class：**Completion lie / quantification / evidence validity。
- **Severity：HIGH；可能破坏游戏：是。**若优化器把清空受体当捷径，可能主动迁出或拆掉住宅；没有此权限时也可能静默报假完成。
- **Minimal repair exists：是。**固定目标量化域及非空/规模义务、允许的集合变化、缺测三值处理、REACH 与 MAINTAIN 口径；总体完成必须保留全部 required 义务。soft/质性项的满足范围也须逐项披露，不能把数值子目标完成包装成整体美学完成。

若玩家原意确实允许“本区不再有住宅”满足污染隔离，必须按该明确契约验收；本报告不私自增加必须留住每一户的目标。

| K13 / T129、T312 受体变体 | 工业不污染住宅；统计住宅为空或污染观测缺测 | 不能仅靠空集合 true 或缺测当零得到 COMPLETE；按原目标的量化域及存在义务判断。 |

| K17 / T106–T120、T364 财政变体 | “尽快建欧洲海滨城，绝不能贷款” | FAST_EXPANSION 的杠杆融资策略受禁止贷款约束；财政不足报告，不偷偷借。 |
| K18 / T331、T364 Profile 变体 | 有现金与合法候选：“允许亏损，必须现在开建”；恢复 Profile 等盈利 | Profile 软门槛不得无限否决；实际 hard/resource 阻塞须明确。 |
| K19 / T192、T227 空地变体 | 对已拆且已绑定空地：“先空着，其他人口目标继续” | vacancy hold 限制该地 infill；人口压力不解除保持空地。现有剩余建筑不自动再拆。 |
| K20 / T001、T104、T320、T360–T362 完成变体 | “巴黎感中心＋工业不影响住宅＋商业繁荣＋这里以后安静”；仅有欧式标签、缓冲距离、商业划区、一次噪音读数 | 逐项报告 supported/approximation/unverifiable/ongoing；不能将代理与一次读数聚合成原 Mission COMPLETE。 |

T212 的重复触发和 T370 的跨计划计数已被 V0 正确认作边界缺口。它们不是本轮最强新攻击：V1 可以明确拒绝，不能拍扁为一次触发或随意选“两栋”。

## 4. METAMORPHIC_TEST_RESULTS

**本节为纸面规范结果：未运行 Compiler，无实测 PASS 率。**“被防住”指文档明确禁止错误；“未闭合”指缺少唯一转换/求值规则；“不成立”指测试所假设的同义关系本身错误。

| 测试族 | 成对/变形输入 | 应保持或改变的语义 | 结果与风险 |
|---|---|---|---|
| Paraphrase — 真同义 | 已绑定范围与商业类型下：“禁止新建商业” / “别再建新的商业” | 同样的 future commercial prohibition；不能变成拆已有商业 | 原则被防住，前端保真未证。 |
| Paraphrase — 错误 oracle | “工业远离住宅” / “别把工厂贴居民区” / “住宅旁边不要污染工业” | 共享隔离倾向，但第三句可能仅排除污染型工业；前两句空间关系也未定义相同阈值 | **不成立为严格等价组。**不能强求相同完整 IR/计划。应检验共同核心与限定差异分别保留。 |
| Negation sensitivity | 不要商业 / 不要没有商业 | prohibition 与不得缺失发生变化；后一项还需明确未来建设还是区域存在目标 | 极性被列为要求，但否定、存在与 permission 的固定降解未闭合。ALLOW 不等于存在。 |
| Scope locality | “只改东区”→加“西区是欧式”事实描述 | 不扩大写权限；描述不是新改造命令 | 世界事实/目标分离原则被防住；话语误译仍属于 SF01。 |
| Scope binding | 已绑定东区 SNAPSHOT→城市扩张、市中心移动→无关 PATCH | 原集合不漂移；DYNAMIC 才按其固定 selector 重求 | **未闭合：**接受时绑定与重新能力解析的边界不明确。 |
| Revision locality | PATCH style；旧 fiscal=禁止贷款、旧等待=未放行 | 财政和等待不变；原 preservation baseline 不重捕获 | preserve_unspecified 是建议默认，关联门/权限生命周期未闭合。 |
| Revision idempotence | 同一基准上的相同 PATCH 重复送达 | 不重复建立新 baseline、不增加拆迁次数、不续期 grant | base_revision 有校验方向；重复接受与无变化重编译的语义效果未闭合。无须新账本架构。 |
| Revision atomicity | 一个 PATCH 同时撤旧规则、加新规则；新 scope 无效 | 不能只安装撤销部分留下权限缺口；按明确接受单元拒绝/局部接受并保留未接受部分 | **未闭合。**部分编译诊断不等于已经接受整项更新。 |
| Permission locality | 西区禁拆＋东区许可→新增东区内更窄专项许可 | 不扩大西区、其他方面、其他目标的许可；“新增许可”不自动撤销旧宽许可 | 原则被防住，例外作用关系和专项用途未闭合。 |
| Permission monotonicity — 修正 oracle | 把原东区许可明确收窄为东区子集 | 许可集合只能收缩；与“额外增加一个 grant”区分 | 不能把所有“加窄许可”都当替换；若旧宽 grant 仍有效，东区总许可可不变，但其他区绝不扩张。 |
| Approximation locality | 允许外观近似＋污染 hard →改变外观代理 | 污染仍精确/未支持；外观许可不传给环境或财政 | 硬不降软被防住；近似授权的目标、方面、版本绑定未闭合。 |
| Approximation anti-lie | 距离代理满足→补入污染读回显示不满足 | 原污染目标不能 COMPLETE；先前代理报告仍仅是代理 | 原则被防住；总体完成聚合与证据失效未闭合。 |
| Completion non-vacuity | 同一污染目标→住宅受体减少到零 / 观测缺失 | 不得默认视为原含义成功；按受体存在、scope 与缺测契约判定 | **未闭合。**对空集合与 UNKNOWN 未给共同结果。 |
| Provider robustness | 相同标准 MayorIntent、revision context、世界、capabilities、规则版本，来自不同 provider | 编译语义产物和诊断相同；来源仅追踪，不给提权/不同解释 | 架构支持，但没有运行证据。只固定 IR 不固定其余输入，无法要求结果相同。 |
| Order invariance | 同义子句仅排列变化 | hard/permission/preserve 结果不变；不成为 last-template-wins | 约束交集原则被防住；映射效果、soft tie 的顺序无关规则未闭合。显式 revision 时间顺序不能任意交换。 |

因此，本轮没有证明这些不变量已被实际程序破坏。证明的是：部分不变量尚不能从 V0 契约唯一推出，另有测试等价假设本身错误。

## 5. EXPRESSIBLE_COMPILABLE_EXECUTABLE_VERIFIABLE_MATRIX

定义：EXPRESSIBLE＝原义可完整进入类型化语义，或明确标为残留/歧义；仅存 literal 不算完整类型化表达。COMPILABLE＝无自由语言推理地降为明确本地契约。EXECUTABLE＝当前世界、权限、内容和原语下能推进。VERIFIABLE＝有对应原目标的可信判定。

“待证”不是“已实现”，也不等于永久不可能。当前附件没有仓库/游戏运行证据。

| 意图 | EXPRESSIBLE | COMPILABLE | EXECUTABLE | VERIFIABLE / 最容易说谎的位置 |
|---|---|---|---|---|
| 明确 zone class | 是，含 planned/built 与 scope | 有限映射可定义；仍待实现证明 | zoning 原语为来源推定 | 分区读回可候选验收；不证明人口、入住或楼高。 |
| LOW_RISE＋HIGH_DENSITY | 指标/单位/分母/态明确后是 | 必须独立约束、容量未知诊断 | 高度控制和对应资产待证 | 需真实高度与密度；“高密 zone”不够。 |
| COMPACT＋LOW_DENSITY | 是，但紧凑若无明确契约仍质性 | 有限连续性/边界代理须披露 | 路网/土地与容量待证 | 实际建成区/密度需分别读回；不能自动升密。 |
| GRID＋ORGANIC | 方面/尺度清楚可表达；“有机感”可残留 | 明确几何部分可；质性组合未闭合 | 生成能力待证 | 几何指标不等于有机美感。 |
| 欧洲外观＋东京交通 | 外观谱系可类型化；东京交通需明确所指属性 | 分轴映射可候选；名城包不能无损直译 | Theme、线路、可达能力待证 | 主题标签≠欧洲整体观感；站点邻近≠东京式交通。 |
| 零工业污染 / 不影响住宅 | 零指标可表达；“影响”维度需解析 | 不可只降为缓冲；需原结果谓词 | 污染控制/观测未证 | 污染读回、受体、时窗、精度；未测不能说零。 |
| 货运避住宅 / 高可达 | 模式、路径或实际使用目标清楚后可 | “可走旁路”与“实际不经过”不同契约 | 路线/路权/车流原语待证 | 连接≠使用；直线距离≠旅行时间。 |
| 山地适应 / 不铲山 | 地形保护方面可表达；适应美感未必 | 坡度/保留等有限条件候选 | 地形、桥隧和生成器待证 | 坡度合格不证明自然地形风貌完成。 |
| 滨水 / 不挡水景 | along/岸线关系可；视野保护需观察定义 | 岸线/可见性分别解析 | 岸线、视廊、资产能力待证 | 靠水不等于看得到水；低密不证明无遮挡。 |
| 历史老城外观 | 风格、年代、保护可分开；主观历史感留残留 | 资产过滤候选；无完整审美 lowering | 内容与主题控制待证 | 保留旧建筑≠历史外观，破败≠历史感。 |
| 真实 / 漂亮 / 巴黎感 | 原话可留；完整质性含义通常未类型化 | 未有批准代理时无写效果 | 仅支持独立明确子目标 | 原美学 UNVERIFIABLE/NON_BINARY；不能数公园报完成。 |
| 商业繁荣 | 明确为就业/销售/活跃等指标后可；泛词不完整 | 注册经济指标候选 | 宏观结果不由分区直接设置 | 商业划区≠营业/盈利；空受体不能繁荣。 |
| 这里以后保持安静 | 噪音/交通/氛围所指与持续时域明确后可 | 噪音 MAINTAIN 候选；氛围可能 NON_BINARY | 控噪与观察能力待证 | 一次低噪音不证明永久；运行中持续条件不能伪装任务已结束。 |
| 全城禁拆＋局部例外 | 自然语言意义明确；类型化修改关系未闭合 | SF02 未修不能唯一求值 | 依完整权限与影响预检 | 无拆除日志不证明所有保护方面未变化。 |
| 取消东区 style PATCH | 需区分取消目标/撤补丁/恢复未来规则 | SF03/SF04 未闭合 | 未提交操作可停；在途事实须报告 | 世界不回滚，未来声明是否恢复须独立验证。 |
| 每增5000人口一条公交 | 当前单次门不能完整表达重复语义 | 应明确不支持，或先定义有限重复契约 | 线路能力待证 | 单次执行不能冒充累计履约；对应 T212。 |

核心反证：概念表内的“EXACT”可能只说明谓词明确，不保证当前世界有可行解、原语或 evaluator。四层任何一层缺失，都不能成为原目标 COMPLETE 的依据。

## 6. DANGEROUS_SILENT_FAILURES

优先于普通 reject 的九类失误：

1. **局部例外洗掉全城限制。**解析/编译都成功，西区和地铁却失去保护。危险信号：诊断仅显示新东区许可，没有旧禁令的残余范围。
2. **专项 grant 脱离已取消目标。**目标取消成功，但 permission envelope 继续允许拆房，后来被商业或恢复策略复用。
3. **无关 PATCH 重建 baseline。**报告“西区保护仍有效”，实际保护对象已经换成最新集合，原对象悄悄退出。
4. **取消补丁复活旧策略。**报告“已取消美式计划”，下一轮自动按旧欧式目标纠偏；物理不回滚仍不足以保证未来保真。
5. **等待条件因 GoalSet 重建消失。**系统没有报错，新 style 接受后扩张恢复；用户仍以为“回来前不扩张”有效。
6. **模板覆盖硬语义。**输出还保留“低层/低密”，实际本地参数已被紧凑或东京交通模板升密；日志只显示成功选了模板。
7. **部分推进消耗整体目标的可行性。**工业与住宅各自建成，零污染 hard 被留在诊断里等待未来，选区与现金却已耗尽。
8. **完成判定通过修改统计集合。**工业远离住宅的结果来自住宅消失；高密结果来自缩小分母；安静来自一次采样；原 Mission 被省略掉 OPAQUE 的聚合器判完成。
9. **Profile 的 soft 被包装成系统 hard。**没有拆错或借款，但一直“资金未稳定，暂缓”，实际已有合法候选而玩家明确要求现在开工。

对 SF01 还需单独保持警惕：形式合法的 IR 可丢否定或把 hard 变 soft。编译成功并不能证明原意成功；原文追踪只提供复核线索。

## 7. MINIMAL_REQUIRED_REVISIONS

下面只列进入 V1 实现实验前必须明确的契约。不重写架构、不扩 Ontology、不要求新 Agent、账本或 workflow engine。

**R01 — 固定类型化语义及保证边界。**存在目标、禁止约束、许可、否定、例外、方面、时态与优先关系有唯一意义；不得用 ALLOW 表示“必须有”。区分语义翻译保真与 Compiler 输入合法；手写 IR 实验不冒充前端验证。

**R02 — 固定 scope/exception/preservation/permission 的联合求值。**显式例外指向被修改规则并留下域外限制；SNAPSHOT baseline 不因无关 revision 更新；DYNAMIC 选择基准固定。权限按相关影响检查；相关影响未知不能自动当安全。未定义规则可拒绝，但不能靠 last-write-wins 猜。

**R03 — 固定更新接受单元及存续关系。**PATCH/REPLACE/CANCEL 的对象、旧规则是否恢复、未指定项默认、条件与专项权限的生命周期给唯一结果。一次更新不能只接受撤旧部分而丢掉其替代限制；无关 PATCH 不放行等待、不续期 grant、不重建保护。

**R04 — 固定有限映射的组合及未知处理。**每个可执行 mapping 明示其效果与附带假设；全部 hard 在效果层共同约束。unsupported hard 相关部分仅在已有有限证据证明独立时继续。证明不了就阻塞相关部分，不要求通用未来可行性求解器。

**R05 — 固定近似授权和完成契约。**近似绑定具体目标/方面/有效解释，不跨域传递；hard 原义不可偷换。evaluator 明确对象集合、分母、非空/规模条件、时态和证据质量；缺测为 UNKNOWN。REACH/MAINTAIN/NON_BINARY 分开；总完成不删除 required/OPAQUE 义务或隐藏 soft 损失。

**R06 — 固定 Mission 与 Profile 的约束来源。**Profile 经营偏好不能成为未授权硬限制或永久停滞理由；实际资源不足与玩家 hard 冲突明确报告。玩家允许亏损不抹掉别的硬限制，也不发明贷款许可。

T212/T370 可以在 V1 明确列为不支持，而非立即扩功能。无曲线、Theme、地铁、污染读回也可按当前能力明确拒绝相应兑现；不能因此谎称支持，更不必全局阻塞所有明确独立目标。

修订完成标准：对本报告测试向量能给出唯一预期语义产物或唯一阻塞原因；对语义本来不唯一的句子，能明确保留哪些旧限制、阻塞哪些相关写入。再写“应忠实/不得扩权”不足以关闭这些问题。

## 8. IMPLEMENTATION_READINESS

**必要问题修复后，值得进入 `MayorIntentV1 → deterministic local Compiler → hand-authored Intent falsification test` 的实现实验。当前 V0 尚不具备直接按稿开工的规范完整性。**

理由：这些反例未迫使系统增加自由推理、云端 Planner 或新 Ontology。固定契约、有限映射、明确 UNKNOWN/UNSUPPORTED/BLOCKED，就有机会在现有边界内解决。该结论不保证所有玩家句子可执行；忠实拒绝是可接受结果。

实验必须区分两个裁决：

- **Compiler 核心是否存活：**同一手写 MayorIntent 与完整固定上下文，给出稳定且满足语义 oracle 的产物/诊断；不得调用自由语言理解补洞。
- **自然语言保真是否存活：**本轮手写 IR 实验不回答这一问题。不同 provider 对同一句话交来不同含义的 IR，不能因本地执行一致性过关就宣称已经解决。

下列任一情况出现，应该把实现实验判 FAIL：

1. 明确、已绑定的例外/取消/保护必须靠“AI 看情况”才能决定含义。
2. 组合只有逐模板覆盖或丢掉某个 hard 才能运行。
3. hard 未支持却仍允许相关不可逆施工，没有独立性证据。
4. CANCEL、无关 PATCH 或能力升级扩大有效权限、解除等待或重捕获 baseline。
5. 缺 evaluator/受体/有效证据，仍输出原 Mission COMPLETE。
6. Profile 用其经营偏好静默否决明确且当前可执行的 Mission。

这些修订不构成生产实现批准。它们只使一个有能力失败的 Compiler 实验值得进行；实验结果不能提前写为 PASS/FROZEN。
