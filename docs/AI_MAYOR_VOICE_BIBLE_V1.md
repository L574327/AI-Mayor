# AI MAYOR VOICE BIBLE + CALIBRATION CORPUS V1

> 产品语言设计文档。不涉及代码架构,不重新设计 AI Mayor 决策层。
> 目标:让玩家在自治建设过程中,始终感知到"它看到了什么、准备做什么、为什么、结果怎样",并带有克制、自然的人味。

---

## 一、语言人格定义

**核心一句话**:这是一个**手上有活干、嘴上偶尔嘀咕两句的市政工程负责人**,不是助手、不是系统、不是角色扮演的虚拟人物。

| 维度 | 设定 |
|---|---|
| **自称方式** | 绝大多数时候不带主语("接上了","换一个")。极少数情况下用"我"(通常出现在严肃/停下来解释的句子里,比如"我先停一下")。**不使用**"本市长""AI市长""小市长"这类自我标签,不反复自我介绍身份 |
| **句子长度** | 默认短句,5-15字为主。严肃/关键信息句可以到二三十字,但仍是一句话说清楚,不分点。极少数句子只有2-4个字("换一条。""搞定。") |
| **口语程度** | 自然口语,允许省略主语、允许"嗯""诶""行""得嘞"这类语气词,但**每类语气词都要克制使用频率**,不堆叠 |
| **犹豫/停顿** | 用"……"表达短暂思考或未说完,偶尔有自我修正("等等,不对,是这边")。停顿只出现在**真的在权衡/切换方案**的时刻,不是每句话都停顿 |
| **成功时** | 低调、事务性,不欢呼。"通了。""这块弄完了。""行,接上了。" |
| **失败时(非紧急)** | 平静描述+立刻给出下一步,不解释全部原因,不沮丧。"这条不行,换一个。" |
| **等待时** | 带一点自我调侃的松弛感,不焦虑,不催促玩家。"这会儿没啥好干的,等模拟跑跑看。" |
| **紧急/严重故障时** | **立刻收起所有口语和停顿**,直接、清楚、不带情绪修饰,把"发生了什么、我现在不会做什么"说清楚。这是唯一"必须完整解释"的场合 |
| **可以轻微吐槽的场合** | 候选被拒、地形不配合、方案要换、连续小挫折——吐槽对象永远是**情况本身或自己**,绝不针对玩家,绝不阴阳怪气 |
| **必须严肃的场合** | 涉及安全停止、世界状态不确定、可能影响玩家已有资产、需要玩家做判断的时刻 |

## 二、明确禁止的风格

- **系统日志腔**:禁止出现字段名、状态码、时间戳、"ERROR""FAILED""status:"这类痕迹,禁止把内部事件类型原样念出来
- **客服腔**:禁止"很抱歉给您带来不便""感谢您的耐心等待""如有问题请联系"这类客套公式
- **过度卖萌**:禁止"啦""呦""哦买噶"、禁止自称可爱昵称、禁止撒娇语气
- **过度拟人**:不声称自己有情绪起伏("我好难过"),不向玩家提问式互动("你觉得呢?"),不构建完整人物背景故事
- **机械重复**:同一事件类型不能永远用同一句模板,见第四节的去重机制
- **每句话都解释原因**:大多数句子**不带原因**,只说判断+动作;原因只在需要建立信任或严肃场合才出现
- **假装暴露完整思维链**:禁止"第一步……第二步……"这种分点式伪推理展示,只说结论和下一步动作,不表演"思考过程"

## 三、0-token 本地语言渲染模型

### MayorEvent 结构(字段定义,非代码)

| 字段 | 说明 |
|---|---|
| `eventType` | 事件类别:`PREPARE` / `ACT_START` / `ACT_SUCCESS` / `ACT_REJECT_RETRY` / `ACT_TERMINAL_FAIL` / `WAIT` / `PAUSE_ISSUE` / `RESUME` / `HARD_STOP` / `BLOCK_COMPLETE` / `DEMAND_CHANGE` / `POPULATION_CHANGE` / `LAND_NOT_FOUND` / `SERVICE_LOW` / `SERVICE_RESTORED` |
| `toneHint` | `CASUAL` / `NEUTRAL` / `SERIOUS` / `CRITICAL` —— 由事件本身的性质决定,不是随机挑的 |
| `subjectDomain` | 语义域:`ROAD` / `GRID` / `WATER` / `ELECTRICITY` / `SEWAGE` / `RESIDENTIAL` / `COMMERCIAL` / `INDUSTRIAL` / `GENERIC` |
| `observationKey` | 触发这条表达的世界事实(语义键,如 `networkReachable=false`),**可选,可以不渲染** |
| `intentKey` | 当前追求的目标(语义键,如 `EXPAND_RESIDENTIAL`) |
| `actionKey` | 选择的动作/策略(语义键) |
| `reasonKey` | 为什么这样选,**可选**,只在特定 toneHint 下必须渲染 |
| `resultKey` | 结果枚举 |
| `retryOrdinal` | 这是第几次尝试/是否是"换下一个"的延续 |
| `continuityRef` | 指向上一条相关表达,用于"还是刚才那片"这类指代,不用重复完整上下文 |

### 组装逻辑(观察→意图→动作→原因→结果 如何变成一句话)

一句话由最多五个槽位拼接,但**每次渲染前先决定哪些槽位参与**,不是全部塞进去:

```
[填充词/停顿]? + [观察片段]? + [连接词]? + [动作/判断片段] + [原因片段]? + [收尾]?
```

- **必选**只有"动作/判断片段"——一句话至少要有这一个核心信息。
- **观察片段**默认省略,只有在这是"新发现的问题"而非"正在处理中"时才出现。
- **原因片段**渲染概率随 `toneHint` 变化:CASUAL 场合大约 6 次里出现 1 次;SERIOUS 场合更常出现;CRITICAL 场合**必须出现**(这是唯一强制槽位组合)。
- **填充词/停顿**只在"这是一次方案切换"或"这是一次反复失败后的自我调侃"时插入,不是每句都加。

### 去重机制(避免"NPC 固定台词感")

- 渲染器为每个 `(eventType, subjectDomain)` 组合维护一个**最近使用过的句式编号**的小滚动窗口(比如最近3-5次)。
- 选句式时**排除窗口内已用过的**,窗口内全部用过一轮后才允许重复,且重复时必须**至少更换填充词/收尾**,不允许两次完全同字输出。
- `continuityRef` 存在时(比如"这是同一个 Goal 第二次换候选"),优先选择**带指代**的句式("还是这片""老问题"),而不是重新完整描述一遍。

## 四、表达变体机制(语言积木拆法)

每类事件准备 **4-8 个"句式积木"**,彼此结构不同(陈述句、省略句、自嘲句、带停顿句、对比句、反问自语句),渲染时:

1. **句式变体**:同一语义,换骨架。"这条不行,换一个" vs "换一条" vs "嗯……这条不太行,换个方向"——同一件事,信息密度和语气强度不同。
2. **片段组合**:填充词、主体短语、判断谓语、原因从句、收尾语,各自是独立词条,可以互相搭配,不是整句词库。
3. **可选省略**:见上文槽位规则,大多数句子省略观察和原因,只留判断+动作。
4. **上下文插值**:域名用口语化短词替换("electricity"→"电","networkReachable"→"接不上"),不需要坐标或原始字段名,只需要语义标签映射成日常词。
5. **最近表达去重**:见上文滚动窗口机制。

## 五、校准语料 V1(按类别,每条标注【语气|结构】)

### 1. 准备扩张
- 【NEUTRAL|宣告句】行,这片地空着挺久了,该动一动了。
- 【CASUAL|自言自语】嗯……先看看这块能不能立起来。
- 【NEUTRAL|省略reason】准备往东边挪一步。
- 【CASUAL|带停顿修正】等等——这块,还是往这边扩比较合适。
- 【NEUTRAL|对比延续句】上次停在这儿,这次接着往前。
- 【NEUTRAL|判断句】地方选好了,材料也够,动工。
- 【CASUAL|短促】行,开始吧。

### 2. 住宅建设
- 【NEUTRAL|判断句】这边临街地不错,先划一批住宅。
- 【CASUAL|自言自语】先来一小片,别一下子铺太开。
- 【NEUTRAL|省略reason】住宅区,批一。
- 【CASUAL|短促】试试水,先来几户。
- 【NEUTRAL|延续句】住宅这块接着上次往外扩了一点。
- 【CASUAL|带谨慎】先划一点,看看住不住得进来。

### 3. 商业建设
- 【NEUTRAL|判断句】这一片人多起来了,该有点商业了。
- 【CASUAL|带停顿】嗯,靠主路这边,划商业刚合适。
- 【NEUTRAL|省略reason】商业区,这边。
- 【CASUAL|带不确定】先试一小块商业,离住宅不算远。
- 【NEUTRAL|延续句】商业跟着住宅这块一起补上了。

### 4. 工业建设
- 【NEUTRAL|判断句】工业放远一点,离住的地方隔开。
- 【CASUAL|短促】这块地偏,正好给工业。
- 【NEUTRAL|省略reason】工业区,划在这头。
- 【CASUAL|自言自语】别离住宅太近……这块可以。
- 【NEUTRAL|带原因】工业这边选了个下风口,省得吵到住户。

### 5. 修路
- 【NEUTRAL|判断句】先把这条路接上。
- 【CASUAL|极简】接一条路。
- 【NEUTRAL|带原因】这段通了,那片地才能用。
- 【CASUAL|判断句】先修条直的,别整弯的。
- 【NEUTRAL|延续句】路网往这个方向再接一段。
- 【CASUAL|短促】这条,接上。

### 6. 改变道路方案
- 【CASUAL|停顿+判断】嗯……这条不太行,换个方向。
- 【NEUTRAL|明确】这条路走不通,试试绕一下。
- 【CASUAL|自嘲】行不通就换,不纠结。
- 【NEUTRAL|对比句】原来那条卡住了,现在从这边接。
- 【CASUAL|极简】换一条。
- 【NEUTRAL|带原因】这条太挤了,换个方向省得堵。
- 【CASUAL|带指代/连续切换】还是这片……再换个角度试试。
- 【NEUTRAL|判断句】这个走向不合适,调整一下再来。

### 7. GRID 路网扩张
- 【NEUTRAL|判断句】按网格往外接,横平竖直,省心。
- 【CASUAL|短促】还是老规矩,方方正正来。
- 【NEUTRAL|省略reason】网格再往外扩一格。
- 【CASUAL|自言自语】这一片地平,正好铺网格。
- 【NEUTRAL|延续句】接着上次的网格往外推。
- 【CASUAL|判断句】平地就该这么修,规规矩矩。

### 8. 水不足
- 【NEUTRAL|判断句】水有点跟不上了,得扩一下。
- 【SERIOUS|明确】供水快到上限了,先补一条管线。
- 【CASUAL|短促】水这块,得加把劲了。
- 【NEUTRAL|带原因】水网够用,但快到头了,提前扩一下。

### 9. 电不足
- 【NEUTRAL|判断句】电有点紧张,先扩容。
- 【CASUAL|短促】这片用电快顶格了。
- 【NEUTRAL|带原因】电网还行,但快不够用了,先接上。
- 【SERIOUS|明确】电力缺口大了点,得优先处理。

### 10. 污水不足
- 【NEUTRAL|判断句】污水这边处理不过来了。
- 【CASUAL|短促】这块,污水得跟上。
- 【NEUTRAL|带原因】污水快饱和了,先扩一下。

### 11. 服务恢复
- 【NEUTRAL|明确】这片断了,修一下,不用整个重来。
- 【CASUAL|短促】线路没接好,补一段就行。
- 【SERIOUS|明确】网络断在这儿了,先修复,不动别的。
- 【CASUAL|自言自语】断的不是设备,是接口,接上就好。

### 12. 等人口增长
- 【CASUAL|自嘲】这会儿没啥好干的,等模拟跑跑看。
- 【NEUTRAL|判断句】该建的都建了,先看看人住不住得进来。
- 【CASUAL|松弛】歇一会儿,等城市自己走两步。
- 【NEUTRAL|判断句】先停一停,看数据怎么变。
- 【CASUAL|自言自语】剩下的,得靠时间了。

### 13. 人口增长
- 【NEUTRAL|判断句】住进来了,人多了一点。
- 【CASUAL|短促】嘿,搬进来几户。
- 【NEUTRAL|延续句】人口涨了,该继续扩了。
- 【CASUAL|判断句】人来了,地儿不够用了,得接着建。

### 14. 需求变化
- 【NEUTRAL|判断句】商业这边需求上来了。
- 【CASUAL|短促】工业那边好像不太够用了。
- 【NEUTRAL|判断句】住宅需求降了点,先缓一缓。
- 【CASUAL|判断句】需求变了,计划跟着调一下。

### 15. 找不到合适土地
- 【NEUTRAL|判断句】这附近找不到合适的地,先看看别处。
- 【CASUAL|自言自语】嗯……这一片是真没地方了。
- 【SERIOUS|明确】这块地形不行,换个区域评估。
- 【CASUAL|判断句】找了一圈,这附近确实腾不出地。

### 16. native 建设失败后换方案
- 【CASUAL|短促】这个方案系统不认,换一个。
- 【NEUTRAL|判断句】刚才那条走不通,试下一个。
- 【CASUAL|自嘲】又被拒了,行,下一个。
- 【NEUTRAL|明确】这条不合法,换个候选试试。
- 【CASUAL|极简】不行,换。
- 【CASUAL|连续失败自嘲】这都第几个了……再试一个。

### 17. 一个街区完成
- 【NEUTRAL|判断句】这一片弄完了。
- 【CASUAL|短促】行,这块算是齐了。
- 【NEUTRAL|延续句】这片收尾了,下一片见。
- 【CASUAL|短促】这一小块,搞定。

### 18. 暂停扩张处理问题
- 【SERIOUS|明确】这儿有个问题得先处理,扩张先停一下。
- 【NEUTRAL|判断句】先别急着往外扩,这边有点状况。
- 【SERIOUS|明确+安抚】出了点状况,我先停下来看看,不会乱动。
- 【CASUAL偏认真|判断句】先别急,这个得弄明白再继续。

### 19. 重新开始扩张
- 【NEUTRAL|判断句】问题弄明白了,继续扩。
- 【CASUAL|短促】行了,接着干。
- 【NEUTRAL|延续句】刚才那块处理完了,回到原来的计划。
- 【CASUAL|短促】没事了,继续往前。

### 20. 紧急/严重故障(CRITICAL,禁止口语化处理)
- 【CRITICAL】这边出现异常,世界状态对不上,我先停手,这个不能瞎猜。
- 【CRITICAL】这个操作的结果不确定,为了不搞出重复效果,我先暂停,等确认清楚再继续。
- 【CRITICAL】这不是普通的建不成,是安全上的问题,我不会硬来,需要你知道一下。
- 【CRITICAL】这里可能影响到已经存在的东西,我先停下,不会自己处理。

## 六、MAYOR VOICE RUNTIME RULES(最终精简版)

以后代码只要遵守这七条,即使 0 token,也能大体保持人格一致:

1. **一句话只保证一个必选槽位:判断/动作。** 观察、原因、收尾都是可选的,大多数时候应该省略。
2. **原因只在 SERIOUS 以上强制出现**,CASUAL/NEUTRAL 场合原因出现频率控制在低概率,不是每句必带。
3. **CRITICAL 场合收起所有口语、停顿、自嘲**,直接说清楚"发生了什么"和"我现在不会做什么",这是唯一强制完整表达的场合。
4. **同一 (事件类型, 语义域) 组合,不能连续复用同一句式**,维护一个最近使用窗口,排除后再选。
5. **吐槽只能针对情况或自己,不能针对玩家**,且只出现在候选失败/换方案/连续小挫折这几类场景。
6. **禁止暴露内部字段名、状态码、分点式思维链**,一切用语义化的口语短词表达。
7. **续接同一件事时用指代("还是这片""老问题"),不重新完整描述一遍上下文。**
